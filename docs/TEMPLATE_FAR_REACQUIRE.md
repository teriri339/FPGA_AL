# 近邻优先、扩大最后位置/中央附近找回

## 范围与设计

用户选择保留快速找回优先，扩大最后可靠位置和画面中央附近；不是全画面检测。以资源优化A为实际基线，保留80×80 ERAM搜索块、64点零均值SAD、13654时钟上限、冻结模板、原误差/唯一性门限和连续3帧确认。

LOST时每三个失败的近邻窗口之后插入一个远邻窗口。近邻仍按原来的32个窗口顺序运行，不因远邻窗口而推进近邻游标；最先两个窗口仍是最后位置、中央。远邻为9×9、间隔16处理像素的网格，偏移-64..+64，跳过原来已覆盖的内3×3。72个网格点分别检查最后位置、中央两个锚点，共144个远邻窗口。每帧仍只捕获、计算一个块，不加整帧缓存或DDR访问。

名义总覆盖由每个锚点约±25扩大到约±73个720p处理像素（不是显示器放大后的像素）。边缘处窗口中心钳位到合法范围，重复窗口不合并。完整远邻轮询需要576个持续失败的搜索帧；60fps且每帧均正常参与搜索时约9.6秒，再加候选确认。出现VERIFY后失败、帧缺失或目标持续移动时可能更久，这不是保证的恢复时间。近邻32窗口周期也会因插入远邻而延长到约43个失败搜索帧。

远邻只提出候选，不直接重置可靠中心或重新学习模板。仍需连续3帧匹配才由VERIFY转TRACK，闪现、错误目标、低唯一性、缺帧和计算超时不能直接锁定。相似外观仍可能误锁，不能保证目标身份；不支持全画面、旋转/尺度变化、动画变形或严重失焦。

## 开源借鉴

参考[CFtld](https://github.com/klahaag/CFtld)的候选建议与短期跟踪验证分离思路。其README明确检测级联只提出位置，由跟踪器决定是否接受；工程是C++/OpenCV、GPL-3.0，不是可直接移植的安路RTL。本次没有导入该项目源码，也没有声称实现KCF、DSST或完整TLD；新增网格调度和确认衔接独立实现。

KEY3长按中央选定/解除、短按曝光；KEY2短按模式、长按RAW锐化不变。默认RAW锐化关闭，OSD/Logo位于显示处理之后；未修改曝光/增益、摄像头模式、分辨率/帧率、引脚、镜头、Canny、颜色跟踪或DDR。AP E/A/D仍是成功I2C写表后的曝光/增益快照，不是寄存器读回。
