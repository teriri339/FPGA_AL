# 板上白场自标定

本文件对应之前发布的可选自标定位流。由于该版固定 AWB，标定前可能呈现明显整体偏绿；用户反馈操作繁琐后，主工程默认已改为 [免操作轻度补偿](WHITE_FIELD_SOFT_PRESET.md)。不要把本文件的长按流程用于新的免操作版。

旧版本仍偏绿的直接原因：原工程在 2026-10-17 14:58 生成的位流未实例化 LSC，之前验证用的合成表也不是实际摄像头的标定表。本版本将采集、求增益、更新表和实时补偿接成可操作的板上流程，不再要求先导出数字帧。

## 上板操作

1. 使用本次单独发布的 `bitstreams/camera_whitefield_selfcal_20261017.bit`，不要继续烧录原 `best_result` 中 14:58 的文件。
2. 在均匀照明下，用哑光白板或干净白纸覆盖整个摄像头视场，避免阴影、反光及过曝。应拍白板本身，不要拍显示屏。保持光源、镜头和白板不动。
3. 长按 KEY2 约两秒。右上角状态条变蓝，显示强制回到 RGB 原图；若原来是 AUTO，自动切换到手动 EXP0。原先已选手动档则保持该档。固定全局 AWB，等待 8 帧使配置和 DDR 画面稳定，再平均采集 16 帧。
4. 等右上角变绿，再移开白板拍摄真实场景。绿条表示标定表已计算完成并应用。蓝条持续期间按 KEY3 不会改变曝光。
5. 红条表示白场过暗或过曝，校正保持关闭。调整光照或短按 KEY3 改变曝光档，再覆盖白板、长按 KEY2 重试。不要对白色不足整个视场的正常场景执行标定。

灰条=尚未标定；蓝条=标定中；绿条=补偿已应用；红条=采集无效。状态条只有右上角 64×6 像素，不遮挡中央画面，也不参与白场采样。

短按 KEY2 仍循环 RAW/GRAY/COLOR/CANNY，改为松手后生效，以区分长按。KEY3 保留 AUTO/EXP0/EXP1/EXP2/EXP3 循环；改变曝光会自动废弃旧系数，状态恢复灰色。校正表暂存在片内 RAM，断电或复位后需要重新标定。更换镜头、光源或明显改变工作条件后也应重新标定。

## 实现

自标定构建使用 `WHITE_FIELD_SELF_CAL=1`、`WHITE_FIELD_SOFT_PRESET=0`、`LSC_ENABLE=1`，`WHITE_FIELD_FIXED_AWB=1`。全局 AWB 固定单位增益，空间补偿同时完成白场的全局中性化和位置相关校正。`hx_white_field_calibrator` 在 DDR 读出的、尚未校正且无 OSD 的 RGB 上采样；正常场景不会自动更新系数。

16×9 个端点节点，各取邻近 8×8 区域，累计 16 帧，每节点每通道共 1024 样本。水平 8 像素先在寄存器累加，再以同步 RAM 保存各节点的逐行总和，避免使用大量触发器保存整套累加器。求平均后，逐通道计算 `gain=round(160*256/mean)`；共享逐位除法器仅在标定阶段运行，实时像素路径继续使用六级双线性插值及饱和乘法。

节点通道均值小于 40、高于 235，或采样区接近饱和的像素比例大于 0.1% 时拒绝标定。该判断不能识别所有非白板场景，白板覆盖和均匀照明仍必须由操作者保证。

校正表写入期间保持原 RGB 输出，最后一个系数写完后等待帧末，再从下一帧完整应用。若标定失败或曝光改变，补偿关闭；不会将半张表应用到画面。标定基于 RGB888，无法恢复传感器/前级 ISP 已经裁剪的高光，也不移除固定污点。

## 验证入口

- `tests/tb_white_field_buttons.sv`：短按/长按区分、单次触发、手动曝光锁定、采集期按键保护和曝光改变时废弃标定。
- `tests/tb_white_field_selfcal.sv`：独立计算全部 144 个 RGB 增益，验证 16 帧采样、正常场景不自动学习、应用前原图直通、帧边界启用、过暗/过曝拒绝和失败恢复。默认 320×180 加速测试；使用 `-gWIDTH=1280 -gHEIGHT=720 -gRUN_FAILURES=0` 测试实际分辨率。
- 之前的静态表、小图、完整分辨率像素比对及 Python 标定测试继续保留。

隔离构建命令：`python tools/prepare_white_field_verification.py <不存在的目录> --on-board --bitstream`。在输出的 `syn_1` 和 `phy_1` 目录依次用 TD 运行 `verify.tcl`。生成测试位流不会自动烧板，也不覆盖原 `best_result`。
