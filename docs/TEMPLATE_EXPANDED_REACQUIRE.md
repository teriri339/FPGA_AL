# LOST 后分阶段邻域搜索

参考 [OAID/ObjectTracker](https://github.com/OAID/ObjectTracker) README 的“重检测只提名候选，跟踪器再次验证”架构。该项目是GPL-3.0 C++软件；本次没有复制、链接或移植其代码，也没有引入KCF/DSST，而是独立扩展现有RTL的搜索调度。

## 调度与边界

原有 TRACK/HOLD 局部匹配不变：80×80片内搜索块、64点零均值SAD、2像素粗搜、两峰1像素细化，局部名义约±9像素。只有 LOST 时增加邻域窗口：

1. 先搜索最后可靠位置，再搜索画面中央。
2. 接着分别搜索两锚点右侧16像素的窗口。
3. 回访原两个锚点，然后再搜索左、下、上、右下、左下、右上、左上邻域；方向偏移均为16像素。
4. 循环32个搜索帧，包含16次锚点回访和16次邻域搜索。每帧仍只捕获/计算一个80×80块，不加整帧缓存、不接DDR。

相邻窗口重叠，合起来对每个锚点提供名义约±25像素的邻域覆盖，而非把一次局部搜索直接扩大到±25。像素单位是1280×720处理坐标，不是拍屏照片或显示缩放后的像素。靠近图像边界时，候选中心夹紧到32..宽/高-32，再按原规则夹紧ROI；部分窗口会重复。不是全画面任意位置找回，更不是旋转/尺度适应。

最坏需要等一轮窗口调度后才轮到相应邻域，再加后续确认帧。32帧只是调度周期，不是保证恢复时限：目标必须停留在覆盖区，大小、方向和图案仍需足够接近初始模板。

## 候选验证与安全行为

原误差/唯一性门限和3帧连续确认不变。LOST候选通过一次检查只进入黄色VERIFY、R:9；随后围绕候选做局部验证，不继续扫其他窗口。满3个连续合格结果才绿色TRACK、R:A，随后正常R:1；此前内部可靠cx/cy不更新，模板始终冻结。

单帧闪现、错误图案、歧义重复纹理、采样不完整和处理超时不能直接恢复TRACK。失败清零确认并回到LOST继续调度。每次重新学习、取消或成功恢复都会清零搜索游标；TRACK/HOLD不启用邻域偏移。

`EXPANDED_REACQUIRE` 默认1；置0保留旧最后位置/中央两窗口调度，用于回归对照。AUTO_REACQUIRE=0仍保持旧LOST停止行为。测试中的旧自动找回场景显式关闭扩展，以继续与旧串行模块比较数学结果；新增默认开启测试独立验证扩展逻辑。

KEY3长按中央选定/解除、短按曝光，KEY2短按模式/长按锐化全部保留。未新增串口或模板数值坐标；顶行TRACK/LOST及C/X/Y/P仍属于颜色跟踪，第三行TPL才属于模板。摄像头/曝光/增益上限/分辨率/帧率/镜头/引脚/DDR/Canny/颜色算法/RAW锐化/OSD数据通路均未修改。
