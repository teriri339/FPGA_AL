## 1. 项目做什么

本项目使用安路 PH1P35A FPGA 接收 SC520 摄像头视频，经 ISP、DDR 帧缓存和流式 RTL 处理后输出 HDMI。当前支持原图/灰度/颜色高亮/边缘显示/梯度灰阶显示、曝光控制、OSD、颜色目标统计、用户中央选定的模板跟踪，以及目标丢失后的粗到细自动找回。

这是传统视觉模板匹配工程，不是 AI 物体分类、目标检测网络或人脸识别。屏幕出现 `TRACK` 不代表系统知道目标是什么类别。

## 3. 视频与统计链路

```text
SC520 → MIPI RX / RAW10 解包 → ISP / demosaic / AWB
      → DDR 帧缓存 → 像素流适配 / 白场补偿
      → 显示模式处理（RAW 可选轻度锐化）
      → 状态文字 / 目标框 / Logo → HDMI

未锐化图像 → 测光、颜色统计、模板特征与匹配
```

显示中的 `RAW` 指 ISP 后的 RGB 原图，不是传感器 Bayer RAW10 文件。锐化是显示支路处理，不反馈给曝光、颜色检测或模板特征。OSD、目标框与安路 Logo 不作为被跟踪的图像内容。

## 4. 按键与快速上手

| 硬件 | 操作 | 效果 |
| --- | --- | --- |
| KEY1，D5 | 按下 | 系统复位，清除当前学习状态 |
| KEY2，A9 | 短按 | RAW → GRAY → COLOR → CANNY → GRAD → RAW（五档循环） |
| KEY2 | 长按约 1 秒 | 切换 RAW 锐化开关；上电默认关闭 |
| KEY3，B9 | 短按并松开 | AUTO → EXP:0 → EXP:1 → EXP:2 → EXP:3 → AUTO |
| KEY3 | 长按约 1 秒 | 学习中央目标，或解除已有模板；不切曝光档位 |
| 蜂鸣器，C12 | 颜色检测从无锁定到锁定 | 约 2 kHz，响约 1 秒 |

短按/长按不要混用，不建议同时按两键。KEY3 短按在松开时执行，避免长按学习同时改变曝光。AE 开启时仍会自行调整，不等于固定曝光。

### 开始一次模板跟踪

1. 先用 RAW 观察，固定相机和照明，确保目标清楚、亮部没有大片发白。
2. 把文字、图案或角点等有辨识度的区域放进中央约 64×64 的选择框。白墙、纯色面和重复条纹不适合作为模板。
3. 稳住目标，长按 KEY3；观察第三行 `TPL`，经过 `LEARN` 后进入 `TRACK`。
4. 缓慢移动目标或相机，观察模板框是否跟随。初次 `TRACK` 只表示学习被接受，仍要观察后续跨帧匹配是否持续可靠。
5. 目标移出视野后，等待 `TPL: LOST`；再将相同目标以接近原大小、角度完整放回画面，停稳等待找回。此时不要按学习键，否则会重新学习而不是验证找回。
6. 要换目标时，TRACK/HOLD 等状态长按 KEY3 解除，再将新目标放中央并长按学习；LOST/FLAT 时可长按重新学习中央区域。

模板框主要叠加在 RAW/GRAY；COLOR/CANNY 保持对应图像算法，TPL 状态仍可观察。

## 5. 如何读 OSD

### 颜色检测与模板跟踪是两套状态

| 字段 | 表示什么 | 不表示什么 |
| --- | --- | --- |
| 顶部 TRACK / HOLD / LOST | 颜色检测的锁定、短暂保持、丢失 | 不是模板状态 |
| C / X / Y / P | 颜色主类、包围框中心、实际颜色像素计数 | 不是模板位置或置信度 |
| 第三行 TPL | 用户学习的模板状态 | 不是红绿蓝检测结果 |
| TPL 后 E / U | 最近完整匹配的总误差、次佳与最佳误差差值，十六进制 | 不是百分比置信度 |
| TPL 后 R / M | 判定原因码、连续失败计数，十六进制 | 不是帧率或串口消息 |

颜色检测默认获取门限 800 像素、锁定后更新门限 400 像素，漏检可保持 10 帧。HOLD 保留上次 C/X/Y，P 仍是实际计数，因此不能把 HOLD 当成新测量。

TPL 常见状态：READY 等待学习、LEARN 采集模板、TRACK 匹配通过、HOLD 暂时不可靠、LOST 丢失并继续找回、FLAT 纹理不足、VERIFY 找回候选确认。TPL 与颜色状态可以一个 TRACK、另一个 LOST，这是正常的独立判定。

### 曝光与增益应用值

示例：`AP E:01990 A:0F D:00/80 OK`。窄字符间距可能使字段看起来挤在一起。

- `EXP:A` 是自动曝光模式；`EXP:0…3` 是手动档位，不是已写入传感器的曝光数值。
- AP 的 `E` 为十进制曝光控制数值，不直接换算为毫秒。
- `A` 为 SC520 `0x3e09` 原始字节；`D` 的两字节依次为 `0x3e06`、`0x3e07`，均以十六进制显示。
- `SC520GainTbl` 的 `I_AG` 是查表索引，不是线性增益倍数；不要把显示字节或索引解释成“几倍”。
- `OK` 表示相应 I2C 写表成功完成；`WR` 表示写入中，`ERR` 表示写入错误。没有成功值时不应把占位信息当作已应用配置。
- 写入失败保留上一份成功值；请求/应答 CDC 快照保证多位数据一起转移。它不是寄存器读回，也不保证当前图像已达到最佳曝光。

**防频闪曝光上限**：默认启用（`ANTI_FLICKER=1`），自动与手动曝光的快门上限都锁在 1200 半行 = 10.0 ms，正好是 50 Hz 市电的一个纹波周期，用来消除弱光下的横向明暗条带。因此 OSD 里的 `E` 不会超过 1200；不足的光量由增益补，暗光下噪声会比旧版略高。60 Hz 市电地区应把 `AE_EXPOSURE_MAX_FLICKER` 改为 `16'd1000`。需要极限暗光且能接受条带时把 `ANTI_FLICKER` 置 0，即回到原来的 1990 上限。手动档 EXP2/EXP3 在启用防频闪后与 EXP1 共用快门、改由增益区分亮度。详见 [AE 频闪与过曝修复](AE_FLICKER_AND_HIGHLIGHT.md)。

**过曝判定**：高光统计改为「任一颜色通道接近削顶且整体亮度不低」，不再只看 BT.601 灰度。暖光灯具（如 R=255/G=200/B=180，灰度仅 214）以前会被 AE 漏判成不过曝，现在能正确识别；同时不会把大面积低亮度饱和色物体误判成过曝。

## 6. 锐化与画质边界

RAW 可选 3×3 轻度亮度域锐化，默认噪声门限 6、最大亮度增量幅度 8、增益移位 1（半增益）。参数见 `hx_vision_pipeline.v` 的 `RAW_SHARPEN_*`。

开启时 OSD 显示 `RAWSHARP`。这是保守的边缘增强，正常情况下不会让整幅图明显变亮；画面本身细节少时差异可能很小。比较时应固定机位、目标和实际曝光值，只切换锐化。

锐化不能恢复失焦、过曝、远处细字像素不足、镜头分辨率不足或运动模糊造成的信息丢失。Canny 也是边缘提取，不负责还原物体纹理。当前不承诺达到手机相机的成像质量。

## 7. 跟踪与自动找回的实现范围

模板采用稀疏亮度样本与零均值 SAD 匹配，局部搜索包含细化；初始模板冻结，避免逐帧更新导致背景漂移。零均值只补偿部分加性亮度变化，并不保证对增益、白平衡和照明变化不敏感。

丢失后保留模板：优先考虑最后位置、中央及扩展邻域，并保留慢速全画面分片扫描兜底。快速路径将图像做 4×4 均值缩小到 320×180，冻结完整快照，在缩小图上找候选，再送原分辨率匹配器验证。候选不能直接宣布 TRACK，仍需误差、局部唯一性和连续三帧确认。

粗到细结构不改变 HDMI 活动分辨率，也不是每帧同时完成全画面精匹配。历史合成 720p 场景约 0.617 秒恢复，仅是特定仿真结果，不是任意实景的时间保证；候选不合格时慢速兜底可能明显更久。

模板框显示坐标与跟踪坐标已分离：搜索中心仍每帧直接跳到 SAD 峰值（跟踪能力与丢失判定不变），送 OSD 的框坐标走「死区 + 每帧一步」的一阶逼近，用于抑制静止场景下 ±1~3 像素的框抖动。代价是匀速运动约 4 帧（≈67 ms）的固定滞后，可用 `TEMPLATE_DISP_SMOOTH_SHIFT` / `TEMPLATE_DISP_DEADBAND` 调整，置 0 即关闭。详见 [模板框显示平滑](TEMPLATE_DISPLAY_SMOOTH.md)。

未实现：尺度自适应、旋转不变匹配、严重遮挡/形变重识别、多目标身份管理、UART 坐标输出、FPS OSD。目标拉远变小、拉近变大或转动角度后仍可能 LOST；相似图案也可能误锁。有关早期算法、局部范围和历史版本，见 [快速找回](TEMPLATE_FAST_REACQUIRE.md) 与 [资源优化](TEMPLATE_FAST_RESOURCE_OPT.md)。

## 8. 蜂鸣器测试与结论

蜂鸣器由颜色目标锁定的上升沿触发，不由 `TPL: TRACK` 触发。持续颜色 TRACK 不会连续鸣叫；HOLD 内恢复也不重新触发，确认 LOST 后再次 TRACK 才重新鸣叫。

测试方法：先对准白墙或移开彩色物体，等顶部颜色状态变 LOST；再放入足够大的红色/绿色物体，使其变 TRACK，应短鸣约 1 秒。用户于 2026-10-21 按此条件测试后确认“响了”。

当前 RTL/ADC 没有 SW5 输入映射，软件告警默认使能。历史注释中的“SW5 控制”不是已核实的当前 RTL 功能，不能据此保证开关行为；若需查硬件作用须核对该板原理图。
