# 模板匹配 RAM 预取与连续累加

本次借鉴 GitHub 工程的硬件数据流组织，独立实现同步 RAM 预取；不是直接替换跟踪算法，不导入 OpenTLD 的 GPL 代码。

参考：Yiğit Bektaş Gürsoy，MIT 许可的 [Motion_Estimation_Hardware_Verilog](https://github.com/yigitbektasgursoy/Motion_Estimation_Hardware_Verilog)，审阅 HEAD `7e98bef5846b8e11bb74c28b96251ad157637f6e` 的 `rtl/ProcessingElements.v`、`Datapath.v`、`InstantMinComp.v` 和 LICENSE。原项目是普通 SAD、16 路处理元素的块运动估计演示，不是可直接连接本工程的完整物体跟踪器。本工程只借鉴有效数据持续累加的组织思想，不复制其 RTL，也不宣称实现了16路并行。

## 实际改动

- 原 ISSUE→WAIT_READ→ACC 每样本3时钟；现在两拍预热后，ACC 消费样本 n，同时预取 n+2，每时钟累加一个样本。
- 均值与零均值 SAD 仍分两遍计算，候选切换仍重新预热；64点模板、两峰细化、纹理/误差/唯一性门限、冻结模板和3帧找回确认均保留。
- 保持80×80片内块、2像素粗搜、1像素细化、名义约±9像素局部范围。试验过扩大为96×96、约±17像素，但原1像素移动测试出现歧义拒绝，未启用或交付该扩大范围。
- 摄像头、曝光、分辨率、帧率、引脚、镜头、DDR、颜色跟踪、Canny、锐化和既有OSD未修改；不增加串口/数值坐标。

## 验证方法

保留修改前的串行匹配模块作为 `tests/hx_template_tracker_serial_ref.v`，仅测试使用，不加入TD工程。等价测试复用128帧自动找回场景，在两版都完成计算之后，逐项比较状态、坐标、诊断分数/裕量/原因/漏检次数、64字节模板及81个粗搜分数，而非要求不同延迟的内部信号逐拍相同。

原自动找回与细步进、边界、超时、缺采样等回归继续独立运行。新的单元检查要求最长工作时间小于14000时钟（旧版38602，720p名义垂直消隐49500）；实测最长13654时钟，减少64.63%，相同候选数量的计算吞吐约2.83倍；不是相机帧率提高2.83倍。

最终等价测试覆盖122次完整作业，与串行版结果一致。初版比较器与激励同在下降沿运行，采样竞争导致只记录21次比较；已改为上升沿后采样，重跑通过。回归脚本新增明确拒绝日志中的 `** Error:` / `** Fatal:`，避免仿真结束阶段的错误被其他PASS文本掩盖。旧参考模块经文本对照确认与上一发布版完全相同，仅模块名不同。
