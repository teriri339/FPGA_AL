# 坐标问题：移动摄像头下的独立运动目标（2026-10-19）

2026-10-20 实现更新：用户已选定“中央选定目标 → 小范围模板跟踪”，已接入局部零均值SAD模板原型，未新增数值坐标或串口输出。见[实现、限制与验证](LOCAL_TEMPLATE_TRACKING.md)。下文“尚未选定初始化方式”等内容保留为先前分析，不代表当前实现状态；全局运动补偿/任意物体识别仍未实现。

## 最新澄清：相机动，物体静止（覆盖下方旧设想）

用户随后明确目标物体本身静止，只有摄像头运动。因此最终需求应归类为**移动相机下的指定目标跟踪**，而非独立运动分割。下方对独立运动检测的资料只保留为前一步分析，不作为最终实施方案。

在静态场景中，不同物体都随相机运动而在图像中位移。仅估计/扣除全局相机运动，无法确定用户究竟要跟踪哪一个物体。必须先指定目标（例如用户圈定 ROI，或让目标进入中央框后按键锁定），再评估模板/特征匹配、尺度变化、遮挡与重捕获。

需要用户先确认目标及初始化方式。未确认之前不替换现有颜色算法，也不把任意背景变化输出为新的目标坐标。现有 X/Y 是颜色框中心、P 是像素数，不是通用物体位置或第三个坐标。

## 已确认的用户需求

- 目标不是限定红、绿、蓝色块，而是任意运动物体的位置。
- 摄像头本身也会移动。

因此不能把现有颜色统计当作运动坐标，也不能直接把固定相机帧差方案接进来宣称完成。当前 `hx_vision_pipeline.v` 的 X/Y 为颜色联合外接框中心，P 为命中像素数；它没有估计或扣除相机自身运动。

## 算法方向与开源参考

合理的候选链路是：背景匹配 → 全局相机运动估计 → 图像/坐标补偿 → 独立运动残差 → 小区域过滤/连通域 → 目标关联与有限保持 → X/Y/P。全局估计失败应标记不可靠或有限 HOLD，不能发布未经验证的新坐标。

已核对的作者/官方资料：

1. [Samaretas/global-motion-estimation](https://github.com/Samaretas/global-motion-estimation)：MIT；多尺度块匹配、仿射运动模型、剔除局部运动离群值以稳健估计全局运动。适合学习“背景多数运动与局部目标运动分离”，是 Python 算法工程，不是 PH1P35A 可直接使用的 RTL。
2. [OpenCV MotionEstimatorRansacL2](https://docs.opencv.org/4.13.0/d6/dbe/classcv_1_1videostab_1_1MotionEstimatorRansacL2.html)：官方全局二维运动估计接口，支持仿射模型与内点比例控制。适合先建立软件参考与可靠性判断，不代表该器件能直接运行 OpenCV。
3. [sthoduka/fmt_motion_detection](https://github.com/sthoduka/fmt_motion_detection)：GPL-3.0；先用 Fourier–Mellin 做配准，再对配准图像进行时间差分，提取相机运动下的独立运动。依赖 FFTW/OpenCV/Eigen，资源与计算结构不能直接套用到本工程。

以上核对了官方文档/仓库说明；本次未拷贝这些项目代码，未宣称已经完成源码级移植或板上验证。

## 必须区分的限制

- 仅补偿整幅平移，不能等价覆盖明显转动、缩放、透视变化。
- 仿射/单应性也不保证去除近景桌面与远景墙面之间的深度视差，更不能恢复严重运动模糊或滚动快门畸变。
- 自动曝光变化是亮度变化，不能用一个灰度偏移替代几何运动补偿。
- 大幅晃动、背景纹理少或前景占多数时，应拒绝不可信估计。
- 增加 HOLD 只能短暂保留旧坐标，不会纠正错误的运动区域。

当前画质版 Slice 已约 79%，运动补偿的存储、匹配算力、随机访问和时序预算尚未验证。不能承诺现有 PH1P35A 余量可实现任意相机运动、任意物体的稳定检测。
