# 运动目标检测（帧差法）设计方案

> 目标器件：Anlogic PH1P35MDG324-3 ｜ 工具：Tang Dynasty 6.2.168116
>
> 工程入口：`reference_edge_project/td_project/camera_to_dsi_display.al`
>
> 版本说明：本文件是设计草案，运动检测 RTL 尚未实现；资源数据须以本地实际综合/布局报告为准。
>
> 颜色跟踪独立参数：`TARGET_HOLD_FRAMES = 10`；该保持逻辑不是 MOTION 运动判决。

## 1. 目的与范围

在现有 `hx_vision_pipeline` 的四模式（RAW / GRAY / COLOR / CANNY）基础上，新增第五种显示模式 **MOTION**，用硬件逻辑实现基于帧差法的运动检测，并在 HDMI 画面上叠加运动区域提示与运动量统计。

本文覆盖运动检测通路与配套的显示画质优化（§13），不修改 MIPI、ISP、DDR、HDMI 驱动。

### 1.1 验收标准

| 项目 | 状态 / 验收要求 |
| --- | --- |
| 功能 | 目标：MOTION 可经 KEY2 循环进入并显示运动区域；尚未实现、尚未验证 |
| 实时性 | “≤3 帧”仅是待测目标；须从摄像头输入到 HDMI 输出实测，不能由架构估算宣称通过 |
| 误报 | 静态场景连续 10 s 与 AE 变化期间无明显误框，均为待测目标 |
| 资源 | 旧目标 Slice ≤72%、LUT6 ≤62%、ERAM ≤60 已被当前工程实际报告超出，不再作为可行预算；新预算等综合结果 |
| 时序 | 需对最终修改版本重跑布局布线；要求 Setup/Hold WNS 为正且无违例端点，当前无 MOTION 版本结果 |

## 2. 算法选型

| 方案 | 存储需求 | 逻辑复杂度 | 适用性判断 |
| --- | --- | --- | --- |
| **帧差法** | 1 帧降采样 | 低 | ✅ 本方案 |
| 背景建模（高斯/中值） | 多帧统计 + 更新逻辑 | 高 | ❌ 存储与算力都吃不消 |
| 光流（Lucas-Kanade） | 多尺度金字塔 | 很高 | ❌ 720p 实时不现实 |
| 三帧差法 | 2 帧降采样 | 中 | 备选，可抑制“鬼影”，见 §15.3 |

选择帧差法的理由：相较背景建模或光流，计算结构较简单，适合作为硬件实现候选。但跨行块累加、历史帧访问、全局补偿和统计缓存均有实现成本；能否在当前 FPGA/时钟约束下满足资源及时序，须综合与布局布线验证，不能仅凭算法运算量断言可行。

## 3. 算法设计

### 3.1 为什么必须降采样

这是整个方案的硬约束，先算清楚再谈算法。

当前可核对的器件为 PH1P35MDG324，片上 ERAM 共 108 块。现有运动设计不能沿用旧的 47/108 基线：本工程 `reference_edge_project/td_project/camera_to_dsi_display_Runs/phy_1/camera_to_dsi_display_phy.area` 实际报告为 **56/108 ERAM、16,357/21,216 Slice（77.10%）、14,232/21,216 LUT6（67.08%）、14,809 寄存器、24/40 DSP**。因此该报告对应构建仅剩 52 块 ERAM，且 LUT6/Slice 已超过旧目标；加入任何逻辑后的资源量必须重新综合确认。

160×90 运动网格共有 14,400 个单元。存储预算必须同时考虑总位数、宏支持的宽深组合、读写端口数、冲突行为和布局布线，而不能只按“一像素一个地址”推断：

| 数据 | 逻辑数据量 | 粗略容量判断 | 必须核对的实现条件 |
| --- | ---: | --- | --- |
| 8-bit 块均值历史 | 115,200 bit | 若保持 2048 地址 × 10 bit 的窄字实现，约需 8 块； | 厂商 ERAM 合法宽深组合、逐字节打包方案与读延迟 |
| 1-bit 二值运动图 | 14,400 bit | 每个 10-bit 字打包 10 个单元需 1,440 地址，容量上可落入 1 块 20K ERAM；双缓冲容量下限为 2 块 | 目标宽度是否支持、bank 读写端口是否足够、打包/解包时序 |
| 1-bit 不打包、每单元占一个地址 | 14,400 地址 | 在 2048 深度配置下需 8 块 | 这是实现选择，不是总位数的必然结论 |

因此“降低位宽完全不能节省块数”不成立。表中是容量下限/粗略映射，不是 Tang Dynasty 综合结果；不可据此承诺实际只用 1 或 2 块。当前报告剩余 52 块也不是可直接分配给本功能的预算，应考虑其他改动和布线余量。

### 3.2 块均值降采样

不做点采样（直接取每 8 个像素中的一个），而是做 8×8 块均值：

```text
mean[x,y] = (Σ 8×8 块内灰度) >> 6      // 64 个像素，累加需 14 bit
```

块均值的两个好处：

1. 对相互独立的随机噪声，块平均理论上可降低标准差；实际传感器/ISP 噪声是否独立、是否随空间相关和增益变化须测量，因此不能固定宣称压低 8 倍；
2. 块均值相较点采样可降低部分像素级抖动影响，但仍可能在网格边界产生量化跳变，须用移动目标样例评估。

降采样后得到 **160 × 90 = 14,400** 个运动网格单元。

### 3.3 帧差与阈值判决

```text
local_delta = signed(mean_now) - signed(mean_prev)
residual    = abs(local_delta - signed(global_shift))
motion      = (residual > T_luma)
```

差分与补偿必须先按有符号量相减，再取绝对值。`global_shift` 的定义、帧对齐限制与可行实现见 §3.4。以下阈值仅是参考模型的起始参数，需用仿真数据和实板噪声重新标定，不能视为已验证的推荐值。

阈值可按经验证的亮度区间做初始分档；与现有 Canny 门限相似不代表二者具有相同统计分布：

| 场景 | 全局平均亮度 | 阈值 T_luma |
| --- | --- | ---: |
| 暗区（高增益、噪声大） | < 96 | 18 |
| 普通室内 | 96 ~ 176 | 14 |
| 明亮场景 | ≥ 176 | 12 |

### 3.4 全局亮度漂移补偿

自动曝光/增益变化可能造成整帧亮度阶跃，裸帧差会把这类全局变化大量判成运动。但全局亮度必须保留方向；绝对值不能提前丢掉符号。

参考定义：

```text
local_delta  = signed(mean_now - mean_prev)
global_shift = signed(global_luma_now - global_luma_prev)
residual     = abs(local_delta - global_shift)
motion       = residual > T_luma
```

例如全局变亮 20、某块却变暗 20，则 `local_delta=-20`、`global_shift=+20`，正确残差为 40；先对局部差取绝对值再减全局差会错误地得到 0。

**重要帧对齐限制：** `global_luma_now` 只有在整帧统计完成后才知道，无法直接补偿同一帧中已经逐块作出的判决。把已完成帧的 `ΔG` 原样套到下一帧也不保证正确，可能过度补偿。实现前必须在以下方案中选定并验证：

1. 将当前帧块均值/差值暂存，帧末得到 `ΔG` 后再做第二遍判决；或
2. 将 AE 曝光/增益更新事件及其生效帧同步送入像素域，在受影响帧冻结或降低置信度，并对全局偏移估计另做同帧一致性处理；或
3. 先不做数值补偿，只检测到全局阶跃后抑制该帧/短窗口，并量化漏检与误检代价。

当前工程的 `O_frame_luma` 在 `frame_start` 发布上一帧采样统计，虽然与视觉处理同属 HDMI 像素时钟域，但这并不自动解决“本帧全局量在帧末才可得”的依赖。必须以帧序号、AE 更新生效时刻及流水延迟对齐。冻结帧数、触发阈值和恢复条件均为待标定参数，不预设“4 帧”已经足够。

```verilog
// 示意：先做有符号差和补偿，再取绝对值；位宽/符号扩展须在 RTL 中显式验证。
wire signed [9:0] local_delta = $signed({1'b0, mean_now}) - $signed({1'b0, mean_prev});
wire signed [9:0] residual_s  = local_delta - global_shift_signed;
wire [9:0] residual_abs = residual_s[9] ? -residual_s : residual_s;
wire motion = (residual_abs > threshold_luma) && !frame_suppress;
```

上例只说明运算顺序，不是可直接综合的最终实现：需验证有符号扩展、最小负数取绝对值范围、补偿估计的帧对齐及流水握手。

### 3.5 形态学清洗

帧差法可能在运动物体的前后边缘产生细条，也会产生孤立噪点。不能先膨胀再声称清除原始孤点：单个 1 经 3×3 膨胀会成为 3×3 的 9 个 1，之后每个点都有邻居，孤点已经无法识别。

建议先在**原始运动图**上做有支撑判定，再按需要做连接/加粗：

```text
motion_raw → 3×3 邻域支撑过滤（去原始孤点） → 可选 3×3 膨胀/受限连接 → 运动区域统计
```

支撑过滤的规则不能只看“开/关运算”的名字：简单要求至少一个邻居会删除真正单格目标或细线端点；采用更严格的邻居数又可能损伤一格宽运动边缘。须用单点、短线、斜线、边界目标、相邻小物体等参考样例量化取舍。必要时将原始判决与滤波结果同时保留，以免形态学把物体并成过大的包围盒。

一个 160×90 网格的 3×3 窗口至少需要跨行状态。若只处理网格点流，理想化的两行 160-bit 历史为 320 bit，但实际 ERAM/LUT 映射、窗口延迟、行首/帧首清空和目标输出流水仍需综合及仿真核验；“每八个视频时钟就有八拍余量”不能代替接口级时序分析。

### 3.7 行级条带抑制（防频闪误报的保险丝）

卷帘快门或光源频闪可能造成横向条带，表现为某些网格行内大量变化。全局均值补偿只能处理近似全局偏移，不能保证去除空间不均匀条带。

若采用“单行运动格数达到阈值则忽略该行”的策略，必须先保留该行的统计结果，再于行尾决定是否并入帧级面积和包围盒：

```text
row_count / row_bbox 暂存该网格行
row_end: 若 row_count < row_limit，则合并到 frame_count / frame_bbox；否则丢弃该行统计
```

这至少需要行级计数、行级 min/max 和延迟提交状态；仅用 8-bit 计数器、边扫描边累加进全帧统计，无法在行尾撤销已经计入的面积与包围盒。若未来绘制逐格热力图而不只是包围框，还需要缓存整行二值图并在判决后再输出。`70%`（112/160）只是待测起点，真实横贯画面的运动也可能被误杀，不能以“相机固定”为由宣称无代价。列方向条带仍需单独验证。

### 3.6 区域统计与计数

每帧对清洗后的运动网格做统计，结果在**下一帧**用于叠加显示（与现有颜色目标框的机制一致）：

| 输出 | 含义 | 位宽 |
| --- | --- | --- |
| `motion_cells` | 运动网格单元总数 | 15 bit（最大 14,400） |
| `motion_xmin/xmax` | 运动区域包围盒 | 8 bit × 2 |
| `motion_ymin/ymax` | 运动区域包围盒 | 7 bit × 2 |
| `motion_active` | 本帧是否存在运动 | 1 bit |

> 注意：`motion_cells` 是**运动面积**，不等于目标个数。真正的目标计数需要连通域标记，见 §9 P2 阶段。

## 4. 硬件架构

### 4.1 模块划分

新增一个独立模块 `hx_motion_detect.v`，挂在 `hx_vision_pipeline` 内部，与 Canny 支路并行：

```text
                     ┌──────────────────────────────────────┐
  灰度 gray ────────►│ 块累加 8×8 → 均值 → 帧差 → 阈值判决   │
                     │        ↑              │              │
                     │   块均值 ERAM         ▼              │
                     │   (8 块, 上一帧)   形态学 3×3          │
                     └───────────────────────┬──────────────┘
                                             ▼
                                    区域统计（包围盒/计数）
                                             │
                        ┌────────────────────┴──────────────┐
                        ▼                                   ▼
                  本帧判决结果                     上一帧统计 → 叠加显示
```

**历史初始化与模式重入：**只有有效历史均值才能参与判决。若非 MOTION 模式关闭 `I_enable` 时也停止历史写入，重入后的历史会陈旧；应在 reset/退出/重入时清除 `history_valid` 并完整预热采集至少一帧，预热帧不输出运动判决，或选择在后台继续更新历史。该策略须纳入接口与逐帧测试，不允许比较未初始化 RAM 内容。

### 4.2 ERAM 访问时序（关键设计）

8×8 块在逐行视频流中并非连续 64 个时钟：同一块跨越 8 条视频扫描线，首个像素行到最后一个像素行的间隔约为 7×1280 个活动像素时钟（还受行消隐影响）。因此“块首读、63 拍后块尾写”的时间图不成立，不能据此证明无冲突。

每个 8 行带需要为 160 个水平块保留跨行部分和；若最终 8×8 累加器需要 14 bit，单是这一组部分和约为 160×14=2,240 bit，另有 11-bit 水平 8 像素和、坐标/有效状态及流水寄存器。需明确这些状态放寄存器还是 RAM，并核对复位与行边界行为。

历史均值的读取、帧差和更新必须依据**真实 ERAM 延迟**安排。可以评估在当前块最终像素组附近发起历史值预读，在块和完成后比较并写入新均值；但具体提前几拍要按原语读延迟与目标时钟实测，不可先假定 1 拍，也不可假定读写同址天然安全。仿真必须使用厂商 ERAM 模型，并验证连续帧、行首/帧首、写后读、模式退出后重进等场景。

地址映射示意：

```text
cell_addr = by * 160 + bx        // by∈[0,89], bx∈[0,159]
                                 // 14,400 个地址 → 8 块 ERAM（每块 2048 深）
```

### 4.3 流水线对齐

| 阶段 | 延迟/状态 | 说明 |
| --- | --- | --- |
| 块累加 | 跨 8 条扫描线 | 不是连续 64 拍；须保留当前 8 行带的部分和 |
| 均值与历史读取 | 由 ERAM 同步读延迟决定 | 具体发读拍、锁存拍、同址读写行为待模型验证 |
| 帧差判决 | 需流水切分 | 有符号差、补偿、绝对值和阈值比较需按 WNS 分级 |
| 形态学 | 至少跨网格行缓存 | 输出坐标必须与邻域中心及边界规则对齐 |
| 行抑制与区域统计 | 先暂存行统计、行尾提交 | 防止无法撤销的帧级计数与 bbox 污染 |

判决为块级数据，不能直接给同帧逐像素叠加提供完整历史掩码。若仅绘制上一帧统计出的单个包围框，需明确统计发布时刻和视频流水坐标对齐；若要逐格热力图则必须有运动图缓存。包含 DDR 帧缓存、历史预热、计算和输出显示的端到端帧延迟目前未知，“≤3 帧”只能作为待测验收目标。

### 4.4 与自动曝光的接口

`hx_vision_pipeline` 已输出 `O_frame_luma`（8 bit）和 `O_frame_luma_toggle`，且当前统计在 HDMI 像素时钟域产生；可评估复用以避免新增 CDC。但该值在帧首发布的是上一帧采样统计，必须按 toggle/帧序号与块数据流水对齐。它不能让本帧尚未完成的全局均值提前可用，也不能单独解决 §3.4 所述补偿时序问题。

## 5. 接口定义

### 5.1 模块端口

```verilog
module hx_motion_detect #(
    parameter integer IMAGE_WIDTH   = 1280,
    parameter integer BLOCK_SIZE    = 8,
    parameter integer GRID_W        = 160,
    parameter integer GRID_H        = 90,
    parameter [8:0]   THRESH_DARK   = 9'd18,
    parameter [8:0]   THRESH_NORMAL = 9'd14,
    parameter [8:0]   THRESH_BRIGHT = 9'd12
) (
    input  wire        I_clk,          // HDMI 像素时钟 75 MHz
    input  wire        I_rst_n,
    input  wire        I_vsync,
    input  wire        I_de,
    input  wire [7:0]  I_gray,         // BT.601 灰度（已有）
    input  wire [7:0]  I_frame_luma,   // 上一帧全局平均亮度（已有）
    input  wire        I_enable,       // MOTION 模式使能；退出/重入时清历史有效标记并预热，或后台持续更新

    output reg         O_motion_active,
    output reg  [14:0] O_motion_cells,
    output reg  [7:0]  O_bbox_xmin,
    output reg  [7:0]  O_bbox_xmax,
    output reg  [6:0]  O_bbox_ymin,
    output reg  [6:0]  O_bbox_ymax
);
```

### 5.2 模式编码扩展

`I_mode` 由 2 bit 扩展为 **3 bit**：

| 编码 | 模式 | OSD |
| --- | --- | --- |
| `3'd0` | RAW | `RAW` |
| `3'd1` | GRAY | `GRAY` |
| `3'd2` | COLOR | `COLOR` |
| `3'd3` | CANNY | `CANNY` |
| `3'd4` | **MOTION** | `MOTION` |

影响文件：`hx_button_mode_ctrl.v`（`O_mode` 位宽）、`design_top_wrapper.v`（`S_vision_mode` 位宽）、`hx_vision_pipeline.v`（端口、模式译码、OSD）。

OSD 字模需补 **`T`** 与 **`I`** 两个字符（现有字模已有 M / O / N）。

## 7. 时序风险评估

可对照的 `camera_to_dsi_display_pr.timing` 报告记录 SWNS `+0.310 ns`、HWNS `+0.020 ns`、STNS/HTNS `0`、违例端点 `0`；实施中须确认该 timing 与 area 文件对应同一构建。不同构建的 +0.256 ns 等旧值不能外推到本方案。尚无 MOTION 版 WNS。

| 风险点 | 评估 | 缓解措施 |
| --- | --- | --- |
| 块累加/状态缓存 | 部分和跨 8 条行扫描；比较路径和地址扇出未测 | 在结构冻结前做周期级模型，综合后检查关键路径 |
| 帧差与全局补偿 | 有符号差、全局估计对齐、冻结控制可能形成长链 | 分级寄存；明确帧有效/补偿版本的握手 |
| ERAM 历史访问 | 同址读写语义与延迟依赖原语配置 | 厂商模型仿真、检查最终映射与读写冲突 |
| 形态学/行统计 | 需缓存与分段提交，不是“每八拍很宽裕”即可证明 | 明确 valid/坐标延迟，检查帧边界与时序 |
| **显示 mux 加到 `O_rgb` 输出路径** | 可能增加已有输出路径延迟与关键路径 | 对视频标志、像素、检测框和 OSD 同步打拍，并复核输出约束 |

实现后应使用该版本的 `syn_1` 与 `phy_1` 报告填入实际数值；先满足时序，再考虑减少寄存器。正 WNS 只对报告覆盖的时钟和约束路径有效。

## 11. 已知限制

1. **只检测“变化”，不检测“存在”**：目标停下后运动框会消失，这是帧差法的固有限制，不是缺陷。
2. **均匀色块目标只能测到边缘**：孔径问题导致内部无梯度区域不产生差值，包围盒可能偏小。
3. **相机自身抖动**：若支架不稳，全画面都会被判为运动。需要机械固定，或后续增加全局运动补偿（代价高，不在本方案范围）。
4. **运动面积 ≠ 目标个数**：真正的计数需要连通域标记，属 P2。
5. **照明闪烁/滚动条带**：可能造成帧间或行间亮度变化；实际是否出现及其频率关系取决于灯源、传感器滚动快门与曝光配置，需按 §12.6 的记录方案测试。行级抑制是候选策略，不保证能区分条带和真实运动。

## 12. 能力边界量化

### 12.1 检测灵敏度模型

对于理想直线边缘在单个 8×8 块内移动，可用下式作数量级直觉：

```text
|Δmean| ≈ (d / 8) × |ΔI|       （仅为简化模型）
```

`d` 为块内位移（像素，假设不跨越多个块），`ΔI` 为目标/背景灰度差。真实结果还受边缘方向、纹理、物体形状、相邻块、AE、ISP 和阈值影响；帧差检测实际看的是补偿后的残差，不能只用单块平均值判定检测率。

在上述理想假设且无补偿误差下，`T=14` 会给出 `d×|ΔI|>112` 的粗略条件。但由此导出的速度和距离表依赖镜头尺度、帧率与场景，不能作为性能保证；必须由逐像素参考模型、标准测试集和板上测量验证。

### 12.2 空间能力

| 项目 | 数值 |
| --- | --- |
| 网格单元 | 8×8 像素，共 160×90 |
| 包围盒量化误差 | ±8 像素，帧间可能抖动 1 格 |
| 候选最小目标 | 可从约 3×3 网格单元（24×24 像素）开始测试；可靠性未验证 |
| 距离/像素换算 | 目前未标定；须使用实际镜头视场、焦距、裁剪、目标尺寸及成像分辨率计算，并以测试集实测 |

旧文档中“8～12 m 可靠检测”缺少可复现的镜头/目标/照度数据支撑，撤销为能力承诺。当前只能说距离越远，目标在 160×90 网格上的有效运动区域越小，是否超过面积/阈值需实测。

### 12.4 明确做不到的事

1. **静止目标**——帧差的本质是检测变化，人站住不动就消失。
2. **目标计数**——P1 只输出单一包围盒，多人运动会合并成一个大框。
3. **目标分类**——无法区分人、车、宠物。
4. **身份跟踪**——没有目标 ID，框会随画面整体重新计算。
5. **沿光轴运动**——朝镜头走近时成像变化小，检测最弱。
6. **亚像素定位**——精度被 8 像素网格锁死。

### 12.5 典型场景预期表现

| 场景 | 当前可说明的性质 / 待测内容 |
| --- | --- |
| 不同距离的行人/目标 | 网格上目标越小、有效块越少，可能更易低于阈值；无已标定距离或保证范围 |
| 近距离快速移动 | 可能出现双边缘、包围盒扩大或跨网格跳变，需逐场景测试 |
| 缓慢移动 | 当块均值变化低于阈值时可能漏检；检测下限未实测 |
| 静止的人 | 连续帧差最终趋近于零，不会持续作为运动目标检测 |
| 多人同时运动 | 单一包围盒会合并多个区域；目标计数须等连通域实现 |
| LED/交流照明闪烁 | 按实际灯源、传感器模式和曝光配置测试；候选行级抑制可能误删真实横向运动 |
| 相机支架受振 | 相机整体运动可能造成大范围变化/误框，未实现全局运动补偿 |

### 12.6 弱光闪烁与曝光：待核对项

条带、自动曝光振荡与高增益噪声可能表现相似，但其频率/成因须根据实际灯源、滚动快门、传感器寄存器和当前曝光配置测量后区分。现有工程中的曝光值不能在未核对 SC520 数据手册、寄存器定义、VTS/行时长及实际生效时序前换算成毫秒。

此前对“1200 单位等于 10 ms”“1990 单位等于 16.6 ms”、特定 50/100 Hz 的免频闪判断、曝光上限改为 1200、增益步长及噪声标准差等数值均未在本设计中独立验证，**撤销这些结论和 AE 修改建议**。本方案不改传感器曝光范围、抗频闪参数或寄存器表。

验证时分别记录：实际曝光/增益写入与生效帧、画面全局亮度、网格行/列统计、灯源频率和输入输出帧率。只有证据确认成因后，才决定是否采取曝光同步冻结、行级异常抑制、换灯源或 AE 调整；每个改动单独回归。

块均值可降低独立随机噪声的标准差，但真实传感器噪声可能空间相关、随增益/曝光变化或受 ISP 降噪影响，不能用理想的 `σ/√64` 直接承诺对高增益噪声免疫。

## 13. 显示画质优化（候选项，需单独验证）

本节是设计候选，不代表这些方案已经在本工程验证或保证收益。资源、画质和时序均需独立实现测试。候选策略遵循同一条架构原则：

> **增强只改"看到的"，不改"测到的"。**
> 增强级位于 `hx_vision_pipeline` 输出与 HDMI mixer 之间；AE 亮度统计、运动检测、颜色检测的输入全部取自增强前的原始像素。OSD 绘制在增强之后，避免字模颜色被 gamma 拉歪（白字被染成暖白）。

### 13.1 Gamma 校正（候选）

**设计假设**：具体曲线应依据传感器/ISP 输出传递特性、显示器和主观评价选择；不能仅凭“传感器线性、显示器 γ≈2.2”断定当前画面发灰的根因。Gamma 不增加传感器信噪比，暗部噪声也可能一并变明显。

**实现**：RGB888 每拍同时需要 R、G、B 三个独立输入地址的查表结果。可评估三路并行 ROM/分布式 LUT、复制 ROM，或在具有足够时钟倍频和已证明像素对齐的前提下时分查询；单个双端口 ERAM 未必能满足三路独立读。表即使共用同一条曲线，也不等于可以共用一个单读口存储器。查表和所有视频标志须流水对齐。

| 项 | 值 |
| --- | --- |
| 曲线 | BT.709 OETF 或纯 2.2 仅为候选；视觉效果与输入传递函数应实测确定 |
| 资源 | 取决于 ROM 复制、存储端口与映射；不预设“一块 ERAM”或 LUT6 数 |
| 风险 | 可能增加并行读存储、输出流水延迟和路由；须综合/时序验证 |

与 §12.6 的关系：Gamma 只改变显示映射，不会改善采集信噪比，暗部噪声也可能被提亮。频闪、曝光和过曝问题仍须基于传感器/照明实测处理。

### 13.2 直方图自动对比度拉伸

**待验证假设**：在部分场景中较窄的输入动态范围可能让图像观感偏灰；是否适合自动拉伸、目标输出范围及其副作用需用当前 ISP 输出和实拍画面评估。

**实现**（两帧法）：

```text
帧 N：   边扫描边累积 256-bin 直方图（每 bin 20 bit，256×20 = 5 Kbit → 1 ERAM）
帧 N 末：取 0.5% / 99.5% 分位点为 lo / hi（截尾拉伸，抗离群）
帧 N+1：y = (x − lo)·k + 16，k = 219/(hi − lo)
```

分位统计、除法/倒数、像素映射、直方图读写端口和帧间参数更新均需结合目标器件实现；“每 bin 20 bit、总计 5 Kbit”只是逻辑容量估算，不能据此断言恰好映射为 1 块 ERAM，也不能预设只需 1 个 DSP。

**待评估的防抖措施**：

1. `lo/hi` 做指数平滑（EMA，α≈0.25）或加 ±4 死区，否则场景微变导致逐帧增益跳动——这就是显示侧的"闪烁"，与 §12.6 的病不同源但症状相似；
2. 检测到 AE 调整的帧是否冻结拉伸参数、冻结多久及恢复条件，须先定义帧对齐的 AE 事件接口并实测；不预设 `ΔG` 门限或固定冻结帧数。

资源增量未知，须实现并综合后填写；当前 56 块 ERAM、24 DSP 的基线使得未经测量的资源口头估算没有预算意义。

### 13.3 锐化（Peaking，可选）

**为什么**：demosaic 和 ISP 低通后边缘变软；监控画面加轻度锐化后观感"清晰度"提升明显。

**候选实现**：3×3 unsharp mask：`out = in + k·(in − blur)`。若评估该方案，可研究现有 `hx_eram_line_store` 的映射与延迟，但不预设复用必定只需 1 ERAM。

锐化可能放大噪声；系数、亮度条件、增益接口和旁路逻辑均须以画质评估及综合报告决定。资源增量与关键路径未知。

### 13.4 色饱和度增强（可选）

可评估 `C' = gray + k·(C − gray)` 一类饱和度变换，但系数、定点范围、裁剪溢出、BT.601 灰度复用及资源增量须综合和实拍验证。COLOR 阈值调试模式应保持旁路，避免变换后的颜色误导观察。

### 13.5 明确不采用的策略

| 策略 | 不采用原因 |
| --- | --- |
| 策略 | 当前处理意见 |
| --- | --- |
| 时域降噪（3DNR） | 暂不纳入 P1。全分辨率历史帧的位数和 ERAM 深度/端口成本须按具体帧格式计算并综合，不能沿用 369 块估算。 |
| 直方图均衡化 | 暂不纳入 P1；需单独评估逐帧映射稳定性，不能据未经测试的画质判断宣称一定闪烁或被其他算法完全替代。 |
| 局部色调映射（LTM） | 暂不纳入 P1；逻辑/存储/时序成本未测，不引用固定 LUT 数或“资源可支撑”的结论。 |
| 抖动（dithering） | 当前 RGB888 链路未见显式输出位宽削减；若下游实际有量化/截位，需重新评估，当前不列入 P1。 |

### 13.6 落地优先级与总预算

| 优先级 | 项 | 资源结论 |
| --- | --- | --- |
| P1 | Gamma 校正 | 三个并行像素通道的存储组织待实现/综合 |
| P1 | 自动对比度拉伸 | 直方图 RAM、分位统计、除法/倒数及控制资源均待综合 |
| P2 | 锐化 | 行缓存和算术资源待综合 |
| P2 | 色饱和度增强 | 算术、通道位宽与关键路径待综合 |

不提供合并总预算：现有运动检测资源增量未测，显示增强成本也不能按旧估算累加。任何功能落地后须重新生成同一版本的 area/timing 报告，并确认视频标志与 RGB 的端到端流水延迟。

> 与自动校准（白场 LSC）的顺序：LSC 在算法链**之前**修正传感器响应，本节增强在算法链**之后**修正显示响应，二者方向相反、互不干扰。开启 `WHITE_FIELD_SELF_CAL` 不需要改动本节任何内容。
